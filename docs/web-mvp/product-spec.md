# Cloud Inn 网页 MVP 产品规格

## 产品一句话

Cloud Inn 是一个轻量的酒店客房设计与效果图创作游戏：玩家挑选一间客房、放入少量家具、写下风格想象，生成并保存一张属于自己的客房主视觉。

## 首版目标

首版必须让首次访问的玩家在五分钟内完成一次创作，并在重新打开同一浏览器后看见上次的客房与效果图。

核心路径：

1. 打开网页，进入唯一的“客房设计”工作台。
2. 从三种客房模板中选择一种：花园大床房、城市双床房、静谧套房。
3. 从六张家具卡中选取或取消选取；家具只是表达空间布置的意图，不进入自由摆放编辑器。
4. 输入不超过 600 字的风格描述。
5. 点击“生成效果图”，等待单一图片模型返回一张横向主视觉。
6. 点击“重新生成”得到同一设计条件下的新结果。
7. 每次修改与生成结果自动保存到浏览器 IndexedDB；刷新或重新打开后恢复当前作品。

## 范围与验收

| 能力 | 首版行为 | 验收标准 |
| --- | --- | --- |
| 客房选择 | 单选 3 个固定模板 | 切换后当前选择清晰可见，并参与生成 |
| 家具卡片 | 最多 6 个可多选卡片 | 选择状态清晰；可随时取消 |
| 风格描述 | 自由文本，600 字以内 | 空文本不能提交；字数可见 |
| 主视觉生成 | 只调用一个配置好的图片模型 | 成功后显示一张图片；失败后说明可重试的原因 |
| 重新生成 | 保持当前模板、家具和文本 | 得到新图片并替换当前主视觉 |
| 本地保存 | 自动保存“当前作品”与图片 | 同一浏览器重开后恢复 |

首版明确不做：多楼层、经营或财务、客群、公共空间、像素建筑编辑、自由拖拽摆放、账号、云同步、导入导出、签名发布、Tauri、系统钥匙串、双 API 或模型自动回退。

## 体验边界

这不是酒店管理器。模板和家具用于帮助玩家写出空间意图，生成图才是每轮创作的主要回报。页面始终只围绕一间正在设计的客房，避免出现楼层、库存、日结、故障诊断等旧项目概念。

图片在当前浏览器的 IndexedDB 中保存。清除该站点浏览数据会清除作品；首版不提供迁移、恢复或跨设备同步承诺。

## 数据模型

浏览器保存一个 `current` 项目：项目名（暂不在界面编辑）、模板 ID、家具 ID 列表、风格描述、主视觉 data URL 与更新时间。静态模板和家具目录随前端发布，不从旧版内容系统或数据库读取。

## 生成规则

服务端由模板、家具和玩家描述组装提示词，并固定要求“单张、写实客房内景、无人物、无文字或标志、4:3 横向”。玩家浏览器只发送 ID 与描述，永远不持有模型密钥。首版选定一个由环境变量 `CLOUD_INN_IMAGE_MODEL` 指向的图片模型；默认值是 `gemini-3.1-flash-image`。失败时只允许同模型重试。

## 成功指标（首轮试玩）

- 首次打开至第一次点击生成的中位时间低于 3 分钟。
- 有生成权限的试玩中，至少 70% 完成一次成功出图。
- 重新访问时，至少 95% 的兼容浏览器能恢复最近作品（不含玩家自行清除站点数据的情况）。
