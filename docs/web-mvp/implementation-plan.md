# Cloud Inn 网页 MVP 分阶段实施计划

## 目录与迁移策略

旧项目是 `app/`，包含 Tauri、Rust、经营模拟及其可靠性体系。它保持原样，作为可回溯历史，不被网页 MVP 编译、引用或删除。

新项目独立放在 `web-mvp/`：

```text
Cloud Inn/
├── app/                       # 旧版 Tauri 项目，冻结保留
├── docs/web-mvp/              # 新产品规格、计划和接口契约
└── web-mvp/                   # 新版网页应用
    ├── src/                   # React 界面、静态目录、IndexedDB 存储
    └── server/                # 仅服务端运行的图片生成代理
```

安全基线是标签 `cloud-inn-v1-handoff-20260811`（提交 `905d2b0`）。网页工作从分支 `codex/web-mvp` 开始；回看旧版可直接检出该标签。开始实施前不移动、改写或删除 `app/` 的文件。是否在 MVP 验证后归档旧版，是单独的产品决定。

## 阶段 0：产品收敛（已完成）

- 确定唯一循环：选房 → 选家具 → 写描述 → 出图 → 重生成。
- 将不属于循环的经营、楼层、公共空间、账号和桌面能力写入首版排除项。
- 确定浏览器本地保存与单模型、服务端代理边界。

产出：`product-spec.md`、`api-contract.md` 与本计划。

## 阶段 1：可试玩网页骨架（骨架已完成；真实模型验证待配置）

- 建立独立 Vite + React 应用和唯一设计工作台。
- 固定 3 个模板、6 张家具卡和风格文本输入。
- 用 IndexedDB 自动恢复当前作品；没有服务端密钥时仍可完整体验设计与保存。
- 加入 `/api/generate` 的调用状态、重生成入口和错误状态。
- 增加蓝图库：保存已出图客房、打开修改并更新同一张蓝图，为后续建设调用保留稳定输入。

完成条件：本地启动后，选择和描述可以刷新恢复；代理返回图片时，图片立即展示且刷新后还在。

## 阶段 2：接入单模型并内部试玩

- 在部署环境注入服务端密钥，并配置一个明确的图片模型名。
- 通过真实模型验证三种模板、空家具、最大长度描述、超时、限流和供应商失败。
- 收集首批生成样本，调整仅服务端的提示词模板与错误文案。

完成条件：内部试玩者能够连续生成并重生成；浏览器开发者工具、打包产物和本地存储均不出现密钥。

## 阶段 3：上线准备

- 将前端静态站点和代理部署到同一受控站点或明确的受限跨域环境。
- 配置允许来源、每 IP 限流、日志脱敏、超时和成本监控。
- 做桌面与手机浏览器冒烟测试，并记录已验证浏览器版本。

完成条件：公开入口只暴露网页与窄化接口；生成失败不泄露供应商响应或任何凭据。

## MVP 之后再决定

先以试玩数据判断是否需要多个本地作品、作品墙、分享、更多模板或卡片。账号、云同步和自由摆放都必须有独立规格，不能作为首版补丁混入。
